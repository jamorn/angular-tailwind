### 1.2 ปรับปรุง Environment Configuration
- เพิ่ม flag `useMockData` ใน `environment.ts`:
```typescript
export const environment = {
  production: false,
  apiUrl: 'http://localhost:5112',
  useMockData: true  // ควบคุมการใช้งาน Mock Data
}
```

## 2. การปรับปรุง DashboardService
### 2.1 เพิ่มระบบ Data Sharing
- ใช้ `BehaviorSubject` เพื่อแชร์ข้อมูลระหว่าง Components
- ลดการเรียก API ซ้ำซ้อน

### 2.2 การเลือกใช้ข้อมูล
```typescript
const data$ = environment.production || !environment.useMockData
  ? this.http.get<MachineOEEData>(`${this.apiUrl}/GetOEEDaily`)
  : of(mockData as MachineOEEData);
```

### 2.3 วิธีการสลับโหมด
- **Mock Data Mode**: `useMockData: true`
- **Real API Mode**: `useMockData: false`

## 3. การปรับปรุง Components
### 3.1 OeeComponent
- แก้ไขให้ใช้ข้อมูลผ่าน `oeeData$` Observable
- ลดการเรียก API ซ้ำซ้อน

### 3.2 GiveawayComponent
- แก้ไขให้ใช้ข้อมูลผ่าน `oeeData$` Observable
- แชร์ข้อมูลกับ OeeComponent

## 4. ประโยชน์ที่ได้รับ
1. ลดการเรียก API ซ้ำซ้อน
2. สามารถทำงานได้โดยไม่ต้องรัน Backend
3. สลับระหว่าง Mock Data และ Real API ได้ง่าย
4. ข้อมูลระหว่าง Components มีความสอดคล้องกัน

## 5. วิธีการทดสอบ
1. รัน `ng serve`
2. เปิด DevTools (F12) ดู Network tab
3. ตรวจสอบว่าไม่มีการเรียก API ซ้ำซ้อน
4. ทดสอบการสลับ `useMockData` ระหว่าง true/false

## 6. การแก้ไข Dependencies และ Providers
### 6.1 การลบ Provider จาก OeeComponent
```typescript
@Component({
  selector: 'app-oee',
  standalone: true,
  imports: [
    CommonModule,
    HighchartsChartModule
  ],
  // ลบ providers array เพื่อใช้ shared instance จาก root
  templateUrl: './oee.component.html',
  styleUrls: ['./oee.component.css']
})
```

### 6.2 การใช้ Dependency Injection ใน Constructor
```typescript
constructor(
  private dashboardService: DashboardService,
  private chartService: ChartService
) {}
```

### 6.3 ประโยชน์ที่ได้จากการแก้ไข
1. **Single Instance**:
   - ใช้ shared instance จาก root injector
   - ลดการสร้าง service instances ที่ซ้ำซ้อน

2. **State Management**:
   - ข้อมูลถูกแชร์ระหว่าง components
   - ใช้ BehaviorSubject เพื่อจัดการ state

3. **Memory Optimization**:
   - ลดการใช้หน่วยความจำ
   - ใช้ทรัพยากรอย่างมีประสิทธิภาพ

## 7. วิธีการทดสอบ Dependency Injection
1. ตรวจสอบ Network Tab ใน DevTools:
   - ดูการเรียก API เมื่อ `useMockData: false`
   - ไม่มีการเรียก API เมื่อ `useMockData: true`

2. ตรวจสอบ Console:
   - ดู log จาก `loadOEEData()`
   - ตรวจสอบว่าข้อมูลถูกแชร์ระหว่าง components

3. ทดสอบการทำงานร่วมกันของ Components:
   - OeeComponent และ GiveawayComponent ใช้ข้อมูลชุดเดียวกัน
   - การอัพเดทข้อมูลส่งผลถึงทั้งสองส่วน
